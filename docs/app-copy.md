# עריכת טקסטים באפליקציה (app-copy)

מסך CMS לעריכת **כל טקסטי הממשק של האפליקציה** (קופי): אונבורדינג, ניווט,
דשבורד, זמנים, תזכורות והתראות, הגדרות, דיאלוגים ועוד — בלי גרסה חדשה בחנויות.

## איך זה עובד

- קולקציית Firestore בשם `app-copy`: מסמך לכל מפתח טקסט (מזהה המסמך = שם
  המפתח בקבצי ה-i18n של האפליקציה, `koren-tefilla/src/i18n/en.ts`/`he.ts`).
- שדות המסמך: `key`, `he`, `en`, `category`, `description`, `order`,
  `timestamp` (מילישניות — מניע את סנכרון הדלתות באפליקציה).
- האפליקציה מושכת מ-**פרוד** בכל סנכרון (פתיחת אפליקציה) את המסמכים עם
  `timestamp >= watermark` ודורסת את הטקסטים המקומפלים דרך `t()`.
  הטקסטים המקומפלים נשארים fallback — מפתח חסר/מחוק לעולם לא ישבור מסך.
- התראות: הטקסט נקבע בזמן תזמון ההתראה, כך ששינוי חל אחרי הסנכרון
  והתזמון-מחדש הבא (שוטף) — לא רטרואקטיבית על התראות שכבר מתוזמנות.

## זרימת עבודה במסך

1. עורכים עברית/אנגלית ← **"שמירה ל-Stage"** (עם ולידציית placeholders:
   `%s` / `%1$s` חייבים להישמר בדיוק, ואסור לרוקן שדה שהיה מלא).
2. **"פרסום לפרוד"** ← אימות פרוד (כמו במסך התפילות) ← המסך משווה Stage
   מול פרוד ומפרסם רק את המפתחות ששונו, עם `timestamp` חדש.

## הפעלה ראשונית (חד-פעמי)

1. **זריעת הקולקציה** מקבצי ה-i18n של האפליקציה:

   ```bash
   node scripts/seed-app-copy.mjs --dry-run          # תצוגה מקדימה
   SEED_EMAIL=... SEED_PASSWORD=... node scripts/seed-app-copy.mjs              # stage
   SEED_EMAIL=... SEED_PASSWORD=... node scripts/seed-app-copy.mjs --env prod   # prod
   ```

   ברירת המחדל מניחה ש-koren-tefilla משוכפל ליד ריפו זה; אחרת
   `--app-repo /path/to/koren-tefilla`.

   הסקריפט מוסיף רק מפתחות שעדיין לא קיימים בקולקציה, ולעולם לא כותב מחדש
   מסמך קיים — לכן הרצה חוזרת לא יכולה לדרוס עריכה שנעשתה ב-CMS. עד
   2026-09-07 הוא כן דרס: כל מסמך שתוכנו שונה מהקוד, כלומר בדיוק אלה
   שנערכו ידנית. אין להריץ עותק ישן של הסקריפט.

2. **חוקי אבטחה (Firebase console, בשני הפרויקטים):** לאפשר על `app-copy`
   קריאה לכל משתמש מאומת (האפליקציה קוראת עם Anonymous Auth, כמו `toc`)
   וכתיבה למשתמשי ה-CMS בלבד. לדוגמה:

   ```
   match /app-copy/{key} {
     allow read: if request.auth != null;
     allow write: if request.auth != null && request.auth.token.email != null;
   }
   ```

3. אין צורך בפריט Bagel: זרם ה-app-copy באפליקציה נשען ישירות על שאילתת
   הדלתא ב-Firestore (הקולקציה קטנה; שאילתת "אין חדש" מחזירה מסמך אחד לכל
   היותר).

## הוספת מפתח חדש

מפתח חדש נולד בקוד האפליקציה (נוסף ל-`en.ts`/`he.ts` וב-UI) — ואז מריצים
שוב את סקריפט הזריעה כדי שיופיע ב-CMS. מסמך שנוסף רק ב-CMS לא יוצג
באפליקציה (אין קוד שקורא לו) — לכן אין במסך כפתור "הוספת מפתח".

עד שמפתח נזרע, האפליקציה מציגה את הטקסט שבקוד — אז אין דחיפות, רק שאי אפשר
לערוך אותו מכאן.

## בדיקת פערים בין הקוד ל-CMS

```bash
SEED_EMAIL=... SEED_PASSWORD=... node scripts/seed-app-copy.mjs --compare
```

קורא בלבד, לא כותב כלום. מדפיס שלוש רשימות: מפתחות שחסרים ב-CMS, מפתחות
שהטקסט שלהם שונה מהקוד, ומפתחות שכבר לא קיימים בקוד.

הרשימה השנייה היא החשובה. מפתח שמופיע בה הוא מקום שבו ה-CMS גובר על הקוד,
וזה יכול להיות אחד משניים: עריכה מכוונת שנעשתה כאן (ואז הכל תקין), או שינוי
שנעשה בקוד ולא הגיע למשתמשים כי הרשומה כאן דורסת אותו. רק אדם יכול להבחין
ביניהם, ולכן שווה להריץ את זה מדי כמה שבועות.

בריצה ב-2026-09-07 נמצאו 5 שינויים מכוונים שהיו תקועים כך במשך שבועות, מול
17 עריכות מכוונות ב-CMS.

בריפו של האפליקציה יש מאז בדיקת CI (`i18n check`) שנכשלת כשמישהו עורך בקוד
טקסט של מפתח קיים, כדי שזה לא ייווצר מחדש.

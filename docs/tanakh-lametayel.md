# התנ"ך למטייל (tanakh-lametayel)

מסך CMS לניהול תוכן אפליקציית **התנ"ך למטייל**: ערכי המדריך, מיקומי GPS,
תמונות ותרגומים. המסך נבנה בשלבים; מסמך זה מתעדכן עם כל שלב.

## איך זה עובד

- **פרויקט Firebase נפרד** מהתפילה: `koren-tanakh-lametayel`. פרויקט אחד
  בלבד, בלי סטייג'. כל שמירה ב-CMS היא טיוטה; משתמשי האפליקציה רואים רק
  מה שפורסם (שלב 7).
- **החיבור** נעשה כאפליקציית Firebase שלישית בשם `tanakh`
  (`src/firebase_config.ts`, `getTanakhFirebaseApp`), לצד סטייג' ופרוד של
  התפילה. ההגדרות מגיעות ממשתני סביבה `VITE_TLM_FIREBASE_*`.
- **כניסה.** בכניסה למסך מתבקשת סיסמה לפרויקט התנ"ך (אותו מייל כמו ב-CMS,
  סיסמה נפרדת), כמו הכניסה לפרוד במסך התפילות. הכניסה נשמרת עד לסגירת
  הטאב. הקוד ב-`src/views/tanakh/services/tanakhAuthService.ts`.
- **האפליקציה לא קוראת מ-Firestore.** היא מושכת קובץ תוכן אחד מ-Storage
  (`published/`), ולכן אין למשתמש האנונימי של האפליקציה גישה למסד בכלל.
- **קולקציות:** ראו "מודל הנתונים" להלן.

## הפעלה ראשונית (חד-פעמי)

### 1. בקונסולת Firebase (פרויקט `koren-tanakh-lametayel`)

1. **Firestore:** Create database → Standard edition → מזהה `(default)` →
   אזור `me-west1` (או `europe-west1`) → Production mode.
2. **Authentication:** Get started → Sign-in method → **Email/Password**.
   בלשונית Users להוסיף משתמש לכל עורך, עם אותו מייל שיש לו ב-CMS.
3. **Web app:** Project settings → Your apps → `</>` → שם `Koren CMS`, בלי
   Hosting. להעתיק את ערכי `firebaseConfig` (סעיף 2 להלן).
4. **Storage** (דורש תכנית Blaze עם חשבון חיוב): Get started → אותו אזור
   כמו Firestore. נדרש רק להעלאת תמונות ולפרסום (שלב 7); אפשר להשלים
   מאוחר יותר.
5. **חוקי אבטחה:** להדביק את `firebase/tanakh-lametayel/firestore.rules`
   ב-Firestore → Rules, ואת `firebase/tanakh-lametayel/storage.rules`
   ב-Storage → Rules (אחרי שהופעל).

### 2. משתני סביבה

ב-Vercel (Project → Settings → Environment Variables, לכל הסביבות), וב-
`.env.local` לפיתוח מקומי. הערכים מ-`firebaseConfig` של אפליקציית הווב:

```
VITE_TLM_FIREBASE_API_KEY=...
VITE_TLM_FIREBASE_AUTH_DOMAIN=koren-tanakh-lametayel.firebaseapp.com
VITE_TLM_FIREBASE_PROJECT_ID=koren-tanakh-lametayel
VITE_TLM_FIREBASE_STORAGE_BUCKET=koren-tanakh-lametayel.firebasestorage.app
VITE_TLM_FIREBASE_MESSAGING_SENDER_ID=...
VITE_TLM_FIREBASE_APP_ID=...
```

אלה הגדרות ציבוריות של אפליקציית ווב (לא סודות); הגישה נאכפת בחוקי
האבטחה. כשחסר משתנה, המסך מציג בדיוק מה חסר.

### 3. בדיקה

לפתוח את ה-CMS → "התנ"ך למטייל" → להזין סיסמה → המסך מציג "מחובר כ-…"
וספירת ערכים (0 לפני שלב 3). שגיאת קריאה אחרי כניסה מוצלחת = חוקי
האבטחה לא הודבקו.

## מודל הנתונים (שלב 2)

הקוד: `src/views/tanakh/model/`. כל מסך עתידי (עריכה, תרגום, פרסום) עובד
דרך הטיפוסים והפונקציות שם, לא דרך מסמכים "חופשיים".

### קולקציות

| קולקציה / מסמך | תוכן | טיפוס |
|---|---|---|
| `entries/{id}` | ערך במדריך | `Entry` |
| `categories/{key}` | קטגוריה (שם דו-לשוני, אייקון, סדר) | `Category` |
| `glossary/{id}` | מונח במילון התעתיק | `GlossaryTerm` |
| `meta/publish` | מצב הפרסום האחרון | `PublishMeta` |

### עקרונות

- **עברית היא המקור.** כל שדה טקסט דו-לשוני הוא מפה `{ he, en? }`. שפה
  חסרה = האפליקציה מציגה עברית. הוספת שפה = הוספת מפתח ל-`Lang` ב-`types.ts`.
- **מצב תרגום לכל שפת יעד** (`i18n.en`): `machine` (תורגם במכונה) →
  `reviewed` (נבדק) → `approved` (מאושר); `stale` = העברית השתנתה אחרי
  התרגום. הזיהוי לפי `sourceHash` (ראו `hash.ts`): hash של שדות המקור בזמן
  התרגום, מושווה ל-hash הנוכחי.
- **גוף הערך נשמר כטקסט עם סימונים**, לא כבלוקים (`body.ts`): פסקאות
  מופרדות בשורה ריקה; שורה שמתחילה ב-`## ` = כותרת משנה, `> ` = ציטוט
  שאינו פסוק, `~ ` = הערה מדעית. זה הפורמט של הגיליון. ההמרה לבלוקים של
  האפליקציה נעשית בפרסום. למה: העורכים מכירים אותו, התרגום עובד על טקסט
  אחד, ואפשר לשנות את פורמט האפליקציה בלי לגעת בתוכן.
- **פסוקים נשמרים כהפניה בלבד** (`quotes: VerseRef[]` – ספר, פרק, פסוק,
  טווח). הטקסט נשלף בפרסום מהתנ"ך שבאפליקציה, ובאנגלית מתרגום קורן. אין
  הקלדה של פסוקים ואין עותק שני שעלול לסטות מהמקור.
- **הקישורים מהפסוקים לערך** (`anchors`) יושבים בתוך הערך, לא בקובץ נפרד,
  ולכן ניתנים לעריכה.
- **`review: string[]`** – הערות לבדיקה אנושית. ההעברה ממלאת אותו (ציטוט
  שלא זוהה כפסוק, ערך קשור שלא נמצא); מסך העריכה מציג ומאפשר לסמן כטופל.

### אימות (`validate.ts`)

`validateEntry(entry, ctx)` מחזיר רשימת בעיות ברמה `error` (חוסם שמירה:
מזהה לא תקין, כותרת חסרה, קטגוריה לא קיימת, פסוק מחוץ לטווח, הפניה לערך
שלא קיים) או `warning` (לא חוסם: גוף ריק, מיקום מחוץ לאזור המקרא, ערך
קשור שלא קיים, מראה מקום שלא זוהה). `ctx` מספק את מזהי הערכים ומפתחות
הקטגוריות הקיימים; בלעדיו הבדיקות התלויות בהם מדולגות.

טווחי פרקים ופסוקים נבדקים מול `tanakhIndex.json` – עותק של אינדקס
התנ"ך מריפו האפליקציה (39 ספרים, מספר פסוקים לכל פרק). `parseHebrewRef`
מפרק מראה מקום בעברית ("יהושע יח, א") באותו אלגוריתם של האפליקציה.

### המרה מהתוכן הקיים (`fromLegacy.ts`)

`convertLegacyContent(entries, locations, anchors)` ממיר את קובצי התוכן
האפויים של האפליקציה (`entries.json`, `locations.json`, `anchors.json`)
למודל החדש. זה מה שסקריפט ההעברה בשלב 3 מריץ. הבדיקה
`fromLegacy.test.ts` מריצה את ההמרה על התוכן האמיתי כשריפו האפליקציה
משוכפל ליד ריפו זה (`../Tanakh-LaMetayel`), ומוודאת: כל 728 הערכים
עוברים אימות בלי שגיאות, ושום מיקום, תמונה, קישור או ציטוט לא הולך לאיבוד.

מה ההמרה עושה עם מה שלא מתמפה ישירות:

- ציטוט בלי הפניה מזוהה (196 מתוך 665 בתוכן הקיים): נשאר בגוף כ-`> `
  ומקבל הערת `review`. סקריפט ההעברה יכול לספק `resolveQuote` שמזהה
  לפי התאמה לטקסט התנ"ך.
- ערך קשור בלי מזהה (285 מתוך 2,464): זיהוי לפי כותרת, סלחני לכתיב
  מלא/חסר (אותו אלגוריתם של האפליקציה). לא נמצא → הערת `review`.
- קטגוריה מספרית → מפתח לפי `categories.ts` (`LEGACY_CATEGORIES`, גם
  זריעת קולקציית `categories`).

## העברת התוכן הקיים (שלב 3)

סקריפט חד-פעמי: `scripts/tanakh/migrate.ts`. מקור האמת הוא **הגיליון**
(טאב "ערכים"); מריפו האפליקציה נלקח רק מה שאין בגיליון: הקישורים
מהפסוקים לערכים (`anchors.json`), רמת הביטחון של מיקומים שכבר היו
באפליקציה (`locations.json`), וטקסט התנ"ך לזיהוי ציטוטים בלי הפניה.

### הרצה (מהמחשב המקומי)

דרישות: ריפו ה-CMS אחרי `npm install`, ריפו האפליקציה (`Tanakh-LaMetayel`)
משוכפל ליד ריפו ה-CMS (או `--app-repo /path`), ו-`.env.local` עם
`VITE_TLM_FIREBASE_*`.

```bash
# 1. דוח בלבד – שום דבר לא נכתב. לעבור על הדוח לפני הכתיבה.
npx vite-node scripts/tanakh/migrate.ts --report migration-report.txt

# 2. כתיבה ל-Firestore (משתמש CMS של פרויקט התנ"ך)
SEED_EMAIL=... SEED_PASSWORD=... npx vite-node scripts/tanakh/migrate.ts --write
```

ב-Windows (PowerShell): `$env:SEED_EMAIL="..."; $env:SEED_PASSWORD="..."; npx vite-node scripts/tanakh/migrate.ts --write`

אפשרויות נוספות: `--csv file.csv` (קובץ מקומי במקום הורדה), `--sheet-id`,
`--overwrite` (לדרוס ערכים קיימים; בלי זה ערך שכבר ב-Firestore מדולג, כך
שהרצה חוזרת לא מוחקת עריכות שנעשו ב-CMS).

### מה הסקריפט עושה

1. מוריד את הגיליון כ-CSV ומפרק אותו (`fromSheet.ts`, פורט של
   `sheet.ts` באפליקציה). שורת פסוק בצורה `[יהושע יח, א] טקסט` הופכת
   להפניה; עמודת "הערות" נקראת ל-`notes`.
2. **שורות בלי מזהה** (יש כותרת, עמודת id ריקה) מקבלות מזהה: אם הכותרת
   קיימת בתוכן האפוי, המזהה הישן; אחרת מזהה חדש ברצף (`e0695` והלאה).
   הדוח מפרט את ההקצאות ("להעתיק לעמודת id בגיליון"), והערך מסומן
   `review`. (בהרצה הראשונה, 2026-09: 101 שורות כאלה, 98 מהן ערכים
   חדשים שהאפליקציה הייתה מדלגת עליהם.)
3. ממיר למודל החדש (`fromLegacy.ts`). ציטוט בלי הפניה מזוהה לפי הטקסט
   (`quoteResolver.ts`: תומך בניקוד, מקפים, קיצור שם ה', והשמטות "...").
   מיקום שזהה למיקום האפוי שומר את רמת הביטחון שלו; מיקום חדש מהגיליון
   מקבל 1.
4. מאמת כל ערך. שגיאת אימות אחת = לא כותבים כלום.
5. עם `--write`: כותב את 8 הקטגוריות ואת כל הערכים (בקבוצות של 400).

### הדוח

הכותרת מסכמת: כמה ערכים, מיקומים, תמונות, קישורים, פסוקים כהפניה, ציטוטים
שנשארו בגוף לבדיקה, ערכים קשורים שלא נמצאו, ערכים חדשים בגיליון, וערכים
שיש באפליקציה ואין בגיליון (לא יועברו). אחר כך פירוט לפי ערך של כל הערות
ה-`review` והאזהרות. רוב הסימונים הם בעיות בתוכן הקיים (כיתובי תמונות
בעמודת מראי המקום, ערכים קשורים מקוטעים, כותרות משנה בעמודת הפסוקים),
שמסך העריכה יאפשר לסנן ולתקן.
